Infrastructure Automation with Terraform

Greenfield vs Brownfield: Resource Import & Code Generation

Not all infrastructure starts from a blank slate (Greenfield). Most DevOps engineers inherit pre-existing, manually created cloud infrastructure (Brownfield) that must be brought under Terraform management without downtime.

1. The Two Approaches to Importing Infrastructure

┌────────────────────────────────────────┬────────────────────────────────────────┐
│  Legacy Imperative CLI (Pre-1.5.0)     │  Modern Declarative Import (1.5.0+)    │
├────────────────────────────────────────┼────────────────────────────────────────┤
│ 1. Must manually write empty HCL code. │ 1. Declare import {} blocks in HCL.    │
│ 2. Run terraform import <addr> <id>.   │ 2. Run plan with -generate-config-out. │
│ 3. Manually iterate until diff is 0.   │ 3. Terraform generates the exact HCL!  │
└────────────────────────────────────────┴────────────────────────────────────────┘

2. The Modern Declarative import Block (Terraform 1.5+)

In Terraform 1.5.0 and newer, importing is declarative and supports automatic code generation.

Step 1: Declare the import Block

Create a file named imports.tf:

# imports.tf

import {
  to = aws_vpc.imported_vpc
  id = "vpc-0a1b2c3d4e5f67890" # Existing AWS VPC ID
}

import {
  to = aws_security_group.imported_sg
  id = "sg-0987654321fedcba0"  # Existing AWS Security Group ID
}

Step 2: Generate HCL Code Automatically

Run terraform plan with the -generate-config-out flag:

terraform plan -generate-config-out=generated_resources.tf

Terraform queries AWS APIs for vpc-0a1b2c3d4e5f67890 and automatically writes the full resource configuration to generated_resources.tf:

# generated_resources.tf (Generated by Terraform)

resource "aws_vpc" "imported_vpc" {
  cidr_block           = "172.31.0.0/16"
  enable_dns_hostnames = true
  enable_dns_support   = true
  instance_tenancy     = "default"

  tags = {
    Name = "legacy-production-vpc"
  }
}

Step 3: Review and Apply

Review the generated file, clean up any unwanted default arguments, and apply:

terraform apply
# Output:
# Apply complete! Resources: 2 imported, 0 added, 0 changed, 0 destroyed.

3. The Legacy Imperative Method (terraform import)

For reference or older environments:

  1. Write the resource block in main.tf:
    resource "aws_s3_bucket" "legacy_bucket" {
  # Leave empty or add bucket name
  bucket = "my-pre-existing-company-bucket"
}
  2. Run the import command:
    terraform import aws_s3_bucket.legacy_bucket my-pre-existing-company-bucket
  3. Run terraform plan and adjust arguments until Plan: 0 to add, 0 to change, 0 to destroy.
